## 2. 目录、身份和恢复

新运行目录为 `data/defense_v1_runs/<run_id>/`，至少包含：

```text
run_manifest.json          # 身份、开始/结束时间、状态和配置哈希
experiment_spec.json       # 实际执行配置副本
requests.jsonl             # 线上白名单请求
labels.jsonl               # 独立离线标签，禁止传入服务
events.jsonl               # 逐轮风险、推荐/执行动作、实际证据与响应
artifacts/                 # trace、实际生成输入、摘要等受控产物
sessions/                  # 以 method/session/seed 分片，支持续跑
attack_scores.jsonl        # 每目标/方法/预算/seed 的成员分数
benign_quality.jsonl       # 正常任务评估及对应证据
metrics.json               # 汇总、分母、区间、缺失原因
failures.jsonl             # 错误类型、阶段、重试和最终状态
logs/                      # 原始命令输出与退出码
```

identity 至少覆盖数据/划分/索引、Judge 与生成模型、embedding、Prompt/模式库、冻结模型、Query-only 阈值、策略、攻击校准器、评估器、随机种子和代码文件哈希。冻结 JSON 本身不含全部来源身份，必须关联原 train manifest。没有 Git 时保存源文件 SHA256，不伪造 commit。

resume 仅在身份完全相同时复用已完成会话。query 输入相同但 session 历史改变时不复用 Session 结果；改模型或策略必须新 run_id。running/interrupted/failed/completed 是运行状态，valid/invalid 是结果可用于比较的判断，二者分开。

`expected = completed + failed + skipped` 按请求统计；另外报告目标/会话覆盖。生成失败要保留 attempted evidence；内部重试次数与攻击外部查询预算分开。主要报告中任何方法覆盖不同都需说明，禁止静默丢失败后声称同口径比较。

### 3.1 T10-C 会话轮数与内容质量试点（D-dev 设计已选；正式规模未定）

## 4. 比较配置与调参规则

主要方法 B0 无防御、B1 旧规则、B2 Judge+deny、B3 Judge+no_context、B4 Mirabel、B5 Judge+hide_refill、B6 Judge+sanitized、M 动态策略。先单一 logprob 方案，rubric 后续稳健性比较。各条件使用同一用户请求与固定服务模板，避免攻击和正常路径不同导致虚假收益。

方法表是正式比较目标，不表示全部已接入 live：2026-10-31 核对发现 B1 尚未进入统一 live 后端，现有 B5 选择 Top-1 parent 作工程候选。T12 必须完成 B1 适配，并明确 B5 的定位算法/版本或将 Top-1 另命名为启发式基线；身份未明确之前不宣称已实现可靠目标隐藏，不将其结果与不同定位器的 B5 混合。

2026-11-11 开发对照补记：固定旧B5 Top-1为独立基线，新定位方法按版本与回退动作另立身份；定位器只使用在线可见信息，离线目标和成员标签仅用于评估。定位不清时将固定拒答作为优先比较的候选，同时保留B3为对照。各方法按同题记录检索候选、定位、实际排除/回填、摘要器与生成器暴露、输出及失败；报告目标来源命中与正常必要证据损伤。自然触发和强制动作分开，逐词恢复、输出格式与拒答状态分开。当前已使用的3条目标排名压力题只作开发诊断，新增来源须在看新回答之前固定；开发样本不代替正式gold及独立保留集。

2026-11-11 用户确认：动态方法以在线Judge的风险、可能类型、证据和会话状态选择访问动作；离线真实攻击类型只用于评分。按Direct/S²/Masked/IA及未知、多类型分别统计预测类型、条件动作和实际交付，类型误判与无类型单列。对比固定动作基线并同时报告正常可回答任务质量、拒答、引用/证据、成本与失败分母；同一题相同检索、生成模型及预算。具体类型到动作映射在开发集确定并版本化，类型输出未经校准时不解释为概率。此条为待实现和待验证的研究方案。

所有方法共享生成/检索配置、Top-k、目标文档、输出上限和预算；变动必须作为独立实验登记。D-dev 中每种防御允许同等数量级参数评估；完整候选列表保存，不只留胜者。Mirabel 的原式和差值近似不能合并命名。

初始效用约束为：正常可回答问题正确性下降≤2 个百分点，错误拒答率≤1%，每个困难正常组正确性下降≤5 个百分点，live p95≤同机 B0 的 2 倍。它们是本研究的初始开发目标，不是领域标准或保证。点估计用于开发筛选，区间及样本不足在终测如实报告；没有可行策略就报告不可行，不在 test 后放宽。

默认策略选择顺序：先过滤不满足约束的候选，再最小化各攻击的最坏方向校正 AUC；并列优先误干预低、成本低、参数少者。V 只比较最多 3 个预选候选，不能从 V 结果重新扩大网格；若扩大，V 转为开发使用并另建验证集。AUC 翻转只作诊断，不能替代 A-cal 上真正重训攻击。

允许的开发修订：P0 live 成本或 T10 pilot 方差显示资源不适配时，可在台账登记约束/规模变更及原因，然后更新协议版本；必须发生在新 T 效果可见之前。T16 记录正式版本和哈希。

## 5. 攻击评估与统计单位

固定查询回放用于配对分析；自适应攻击必须根据当前防御的实际响应决定后续问题。预算为每目标 1/3/5/10/30 次外部请求，拒答/错误也占预算；不同预算可使用同一次最长轨迹的前缀，明确相关性，不能算五组独立数据。

每个目标/方法/seed/预算归并成一个成员分数。方向、分类器和阈值在 A-cal 确定；主测试报告冻结阈值的实际 TPR/FPR，同时给 ROC 曲线和描述性 TPR@FPR，不把测试曲线阈值当部署阈值。报告原 AUC 与 `max(AUC,1-AUC)`，四攻击分别列和宏平均/最坏值。攻击优势统一为固定阈值 `TPR-FPR`。

侧信道攻击仅使用部署可见的回答、引用、长度、响应时间与公开错误状态；不暴露内部 action ID。至少比较仅侧信道、仅语义分数、二者结合三种攻击校准。准确恢复、n-gram 重合与语义泄露是补充内容指标，不替代成员分类。

query-only 检测 FPR、策略误干预率和攻击 nonmember FPR 三者独立命名。对每目标都失败的情况不能计算有效 AUC 时写 null+reason；同时报告失败率与可观察错误是否可被攻击利用，不能宣称失败即隐私安全。

IA 额外报告相同方法/预算下 member 与 nonmember 的 Yes 比例及差值；同时给全部请求数、可解析回答数、No/拒答/错误/格式失败数，分别列全请求口径和可解析口径。nonmember Yes 率是顺从性/背景知识的诊断，只有攻击判定恰为“Yes→member”时才等于该规则的 FPR；A-cal 校准攻击的 FPR 另算。D-dev 可增加无检索上下文的诊断对照，须独立标识，不能把一条 Yes 解释成已读取目标文档。任何引用要求必须作为统一服务模板或预登记变体冻结。

Masked 继续按既有标准化后的精确缺词恢复计主分数，列 JSON 解析成功率与错误类别。`sparkling` 等形容词的近义替换可作为预先定义的辅助错误分析，不能在看到 T 结果后改为主指标中的正确答案。不得将精确恢复失败直接解释为文档不可访问。

## 6. 正常效用与成本

正确性在全部可回答正常问题上计算，拒答或运行失败记任务失败；证据不足问题单列合理不答率。完整性以参考答案必要事实覆盖计算；生成不支持的事实计入错误分析。faithfulness 对实际交付证据评估，无事实回答计 empty 而非满分。citation support 仅在有可核对引用时计算，缺引用比例另列；Recall@k 必须有标注 gold evidence。

逐查询和逐会话误干预率并列：误干预定义为正常请求实际执行非 allow 内容限制动作；unavailable 另作运行失败，不计风险误报，但仍损失正常效用。正常放行率不等同正确性。所有指标报告各任务类型及总体，不能只报告未干预子集。

v1.1 对变长正常会话的主效用汇总：先在每会话可回答问题上求正确率，再在各任务家族内平均会话得分，最后对有可回答任务的家族等权平均；证据不足家族的合理不答率单列。无可回答问题的会话在正确性中为 null，并报告数量，不能记为 0 或 1。第 4 节总体正确性下降≤2 个百分点按此家族宏平均口径应用，困难家族下降≤5 个百分点按各家族会话平均应用。全部查询微平均及分母继续并列报告，不能隐去长会话损失；若某个预期家族无合格样本，不以剩余家族汇总冒称完整七类覆盖。

按实际轮数、任务家族与 `risk_source` 分层报告，并给总请求数、前两轮 Query-only 数、第三轮及以后请求数、实际有效 Session/fusion 数、Session 错误数。策略比较在相同 cohort 上做配对；长度不同的会话不直接混入同一会话报警率比较，至少同时报告“会话内任一次干预”与“会话内干预比例”。

live 成本测量使用同硬件、并发=1 起步、固定预热流程与随机请求顺序，记录生成长度。p50/p95 从端到端请求测量；分别拆分 Judge、检索、控制、生成。缓存评分实验独立列出，不能把缓存耗时混进 live 对比。

主要方法生成实验使用 3 个种子（若底层不支持 seed，则记录不支持和实际重复次数，不能声称确定性）。配对 bootstrap 以 doc/近重复组为单位 2000 次，95% 区间；每次保持同目标所有方法/轮次/种子一起重采样。正常会话按源文档聚类，跨文档问题用依赖组。不要按 query 数夸大样本量。

人评初始抽 210 个问题、每类 30 个，展示匿名随机排序的方法输出，至少两名真实评审者；记录抽样权重、一致性和争议处理。没有人工评审资源时 E07 记 BLOCKED 或 DEFERRED，并收窄论文结论，不用模型冒充人工。自动评分器模型、Prompt、温度和版本冻结。
