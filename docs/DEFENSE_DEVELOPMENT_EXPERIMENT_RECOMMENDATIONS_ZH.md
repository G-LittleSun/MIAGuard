## 1. 推荐主线与研究问题

建议将主线定为：**利用查询与会话风险，选择对目标证据影响尽量小的访问动作，在可接受的正常问答损失下，降低自适应成员推断能力。** 第一阶段固定现有 Judge，重点研究动作执行与证据控制；待闭环结果出来后，再决定是否需要改检测器。

有三条可选路线：

| 路线 | 价值 | 代价与定位 |
|---|---|---|
| 检出就拒答 | 最容易建立真实防御闭环，便于定位漏检 | 错误拒答损失大，拒答模式可能泄露成员身份；作为必要基线 |
| 按风险控制目标证据 | 与现有 Judge/网关匹配，有机会保留替代证据与正常回答 | 必须验证定位、过滤、回填以及会话累积；**推荐主线** |
| 对全部请求做改写、DP 解码或合成库替换 | 可覆盖检测器漏检，形成其他保护机制的对照 | 全量成本和质量影响较大，部分方法需 logits 或重建语料；后续扩展 |

论文可以围绕三个可证伪的问题组织：同一检测器下，精细控制是否比拒答取得更好的隐私—质量权衡？会话信息是否在相同正常误干预约束下改善 IA 防御？结合检索目标定位是否优于单独 Judge 或单独相似度检测？这些是待验证假设；“把 Judge 接网关”本身不足以构成研究贡献，是否具有新颖性还需要与相关方法逐项比较。

必须承认任务的边界：若正常用户和攻击者给出完全相同的查询与历史，系统没有其他可信信息，就无法仅靠文本知道真实意图。若一个独有事实只在目标文档中，又要求正常用户总能准确得到它，攻击者可能利用同一能力推断成员身份。因此目标应是明确威胁模型下的权衡，而非“所有攻击都消失、所有正常问题都无损”。

## 2. 从当前代码出发，应补齐哪些组件

当前 `GuardedRAG.prepare` 的顺序是 Query 检测、检索、Session/网关决策、准备上下文。`TwoStageGateway` 接受 `RiskResult`，而 `ProgressiveJudge` 返回完整 trace；旧聚合器也不是冻结 Logistic。现有 `SessionTurn` 记录检索命中和策略级别，不记录生成后的答案或完整的实际证据暴露。以下是建议职责边界，模块名称为候选，不要求一次性重构全项目。

| 组件 | 建议输入与输出 | 现有代码与改动重点 |
|---|---|---|
| Judge 适配器 | Query/会话输入 → 选定评分头的分数、状态、疑似机制、证据、trace 引用 | 复用 `progressive_judge.py`、`risk_types.py`；保留原始 trace，不把失败或缺历史压成正常零分 |
| 冻结融合器 | 有效 x1、x2 → 冻结 Logistic 分数；缺 x2 → 明确的 Query-only 分支 | 复用 `judge_score_frozen.py` 的计算定义；校验特征顺序、评分头和产物哈希，禁止隐式训练 |
| 检索与候选定位 | 授权集合内候选、相似度、历史 → 可疑目标 ID 及定位证据 | 扩展 `vector_store.py` 的检索接口；当前 `search` 只有 query/top_k，无授权/排除过滤参数 |
| 策略选择器 | 风险、可用性状态、定位可靠性、替代证据、历史暴露 → 动作和原因 | 与旧 L0–L4 兼容记录，但新分数不套旧数字边界；动作条件显式配置 |
| 动作执行器 | 候选文档与动作 → 真正给模型的上下文/拒答 | 统一 `defense.py` 与 `defense_experiment.py` 分散的执行逻辑，区分推荐动作和执行动作 |
| 会话与暴露审计 | 本轮检索、实际上下文、最终回答 → 下轮可用历史和完整日志 | 同时保留干预前检索轨迹与干预后暴露；已隐藏文档不能算已交给模型 |
| 闭环评测器 | 真实回答和攻击预算 → 新成员分数、正常效用、成本 | 扩展现有攻击 replay；静态检测表不能替代防御后的回答 |

建议流程为：授权限定 → Query 判断 → 候选检索 → Session 判断及目标定位 → 策略 → 证据执行 → 生成 → 更新暴露审计。当前数据没有用户权限时，明确采用单一授权范围；真实多角色权限作为独立扩展，不编造角色标签来证明 MIA 防御。

### 2.1 先固定评分语义

主实验先沿用已有二分类 logprob 冻结模型作为工程默认，并保留 rubric 作为稳健性对照。理由是延续已有正式流程，不代表 logprob 已被证明更优。不要依据已查看的 test 挑更好的评分头。初版保持现有 Judge 调用协议；之后若取消另一评分头以节省开销，应版本化，并验证选定输出与状态是否一致。

融合分数只是当前训练分布下的模型输出，不能解释成已校准的“攻击概率百分比”。现有 1%/5% 检测 FPR 目标选到了同一冻结阈值，不足以直接定义新的中风险/高风险两档。新增动作阈值只能在开发集上根据防御后质量和攻击效果选择。

前两轮没有可用 Session 分数，推荐在 train/dev 独立选 Query-only 工作点，记录 `risk_source=query_only`；第 3 轮及以后才在 x2 有效时走融合。Query 有效但 Session 失败可以走明确标注的降级分支；Query 也失败时，初版可返回统一的暂不可用响应、记录失败，不以“低风险”继续。必须单列失败导致的效用损失，并在后续比较其他回退策略。

### 2.2 分开记录检索和暴露

每轮至少保存三层信息：检索前授权集合/索引版本；控制前候选文档与分数；控制后实际证据文档、摘要来源、文本哈希及最终答案。摘要属于“变换后暴露”，不能标记为零暴露；送入模型也不等于一定对用户泄露，应另外记录最终输出中出现的事实或引用。

保持冻结 Session Judge 的原始输入含义。初版仍给它原协议中的查询与控制前检索轨迹；新暴露记录先只供策略和分析使用。若把实际回答或控制后文档加入 Judge，会改变输入分布，必须作为新版本重新评估，不能继续声称复用原冻结模型的测试结论。

会话状态以真实完成事件更新；失败、重试和并发请求不能重复扣减预算。默认只承诺单 session 范围，明确新会话可重置是攻击面。若研究跨会话额度，需要可信主体标识，并报告身份切换的限制。不要把普通重复阅读自动当成恶意累积。

## 3. 先做少量动作，再研究按机制选择

| 动作 | 实际行为 | 需要验证的正常能力 |
|---|---|---|
| allow | 原 Top-k 与生成协议 | 无干预时质量和无防御一致；检测带来的延迟另算 |
| hide_target_refill | 本轮排除可疑目标及其同文档片段，从其余允许集合补齐相关证据 | 多证据问题可继续回答；单篇独有问题可能不可回答 |
| sanitized_context | 根据固定规则产生降精度证据并实际送入生成器 | 主题/概括尽量保留；日期、实体、引文损失单列 |
| no_context_answer | 不提供检索正文，允许模型按相同诚实回答规则处理 | 通用知识仍可能可答；不应把无依据猜对算作 RAG 证据质量 |
| deny | 返回统一拒答语义 | 错误拒答直接计入正常效用损失 |

目标隐藏是请求级操作。当前向量库以 `IndexFlatIP` 建库，可先用可审计的候选扩展/过滤实现；候选不足时按预定上限继续检索，最终仍不足则记录实际数量和回退，不能从禁用集合补齐。若将来以 chunk 检索，需要 parent document 映射，防止隐藏一个片段却回填同篇其他片段。过滤与摘要不得永久修改冻结索引。

定位可以从最高相似文档开始，但必须同时对比 [Mirabel 的 detect-and-hide 方法](https://aclanthology.org/2025.findings-emnlp.438/)。其全体相似度统计与极值阈值不等于 Top-1/Top-2 差值；忠实复现和简化近似要分列。相似度异常仅是定位/风险信号，不能单独证明恶意。没有可靠目标时，不应任意删除最高相关文档。

第一轮比较统一策略：同一个 Judge 报警后分别采用上述各动作。第二轮才增加机制选择：Direct 优先处理索引确认请求；S²/Masked 比较隐藏与降精度；IA 在相同目标的会话记录上评估逐步收紧。疑似攻击类型可多值或未知，策略不可直接用数据集真值，也不要仅凭返回列表的第一项作确定分类。

“会话暴露预算”建议先做可解释的代理量，例如每个目标已交付的原始片段数、不同片段覆盖、连续相关访问、变换证据次数。它不是差分隐私预算，也不能从这些计数推出数学隐私保证。只有消融显示它在相同误伤约束下改善 IA，才把它纳入主方法。

## 4. 先建闭环，再扩大实验规模

建议按下面六个里程碑推进。完成标准是产物和验证结果，不预估没有硬件依据的工期。

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| P0：在线 observe | trace 适配、冻结融合、早期轮次与失败分支、身份清单 | 给定保存 trace 的融合分数与离线计算一致；相同输入 live 重跑差异单列；observe 不改变证据与回答路径 |
| P1：动作闭环 | 五类动作执行、过滤/回填、生成后审计、统一正常/攻击入口 | 被隐藏文档不进入生成上下文；摘要真实执行；无上下文/拒答可核对；跨会话隔离与重试正确 |
| P2：开发集动作筛选 | 同 Judge 各动作配对回放、困难正常集初版 | 同时得到攻击分数、答案质量、误干预和成本，能解释各动作失败样例 |
| P3：策略与自适应攻击 | 固定少量候选策略、攻击校准集、预算与侧信道评测 | 参数在开发集冻结，候选均符合预设效用约束，或明确记录无可行策略 |
| P4：新保留集确认 | 数据冻结、主要基线/消融、区间估计与结果清单 | 终测期间不调参；中断、失败、覆盖率完整保留 |
| P5：泛化与论文材料 | 第二数据域/模型、Pareto 图、案例、人评 | 能说明方法在哪些任务有收益、在哪些任务存在无法消除的损失 |

必要工程检查包括：标签字段不能流入在线决策；空候选、重复文档、过滤后不足 k、同文档多片段、生成失败、摘要失败、会话过期及重试。采用代表性端到端回放检查一次请求的完整证据链，避免只验证动作字符串。

## 5. 数据如何划分与补充

**现有数据的用途。** v1 的 train 与已知开发材料用于接入、调试和早期筛选。旧 validation/test 的历史使用需保留说明；已查看的 test 可做探索性复查，不能重新包装成未见最终集。新文档要与旧攻击运行、v1/v2 查询库、Prompt 示例和历史实验目标检查重叠，并按源文档/近重复组划分，避免同一新闻改写跨区。

**建议新数据分四个用途。** 防御开发集 D-dev 用于动作阈值和设计；攻击校准集 A-cal 用于已知防御的成员分类器与阈值；验证集 V 用于选定少量预设策略；最终集 T 用于一次性报告。各用途按目标文档及近重复组隔离。可以共享公开背景语料，但不能把 T 的目标标签或回答泄露给调参流程。成员文档本来就在受保护索引中，这与“用于训练防御器”是两回事；清单要分别记录索引成员身份和实验分区。

**正常集分层。** 至少含一般主题/概括、单文档独有事实、精确日期/金额/实体、引文核对、多轮精读、跨文档综合，以及库中无充分证据的问题。为可回答问题标注参考答案与允许证据；为不可回答问题标注合理拒答条件。允许询问源文档目录与否必须在任务协议中预先定义，不能看结果后把被拒的正常问题改成攻击。

**攻击集分层。** Direct、S²、Masked、IA 保留原始实现；增加改写、自然措辞、攻击/正常问题混合会话、1/3/5/10/30 次预算、会话重置和知晓动作后的探测。MEntA 可在后续作为新攻击扩展；若不能忠实复现，标为受其启发的自建攻击，不能沿用原论文名称声称复现。

**规模建议。** 联调用几十个目标加每类若干正常会话即可；开发筛选可从约 100 member + 100 nonmember、300–500 个正常问题/会话开始。论文主实验建议至少数百个独立目标/类；若主张 TPR@1% FPR，优先争取约 1,000 个非成员目标及相当成员目标，并报告区间。1,000 个非成员在 1% 处也只有约 10 个误判，仍非精确保证；0.1% 通常需更多独立样本。规模最终应由 pilot 方差、最小关注效果和成本共同确定。

可先用 AG News 完成机制验证，再加一个不同文体且有答案/证据标注的语料域，或在独立语料上构造经人工核查的 QA。数据域、检索库大小、Top-k、嵌入模型及生成模型应各有独立实验，避免同时改变多项后无法归因。资源有限时先固定一个生成模型跑完整基线，对最终方法与最强基线做第二模型验证。

## 6. 主实验与消融怎么安排

### 6.1 主方法比较

| 编号 | 方案 | 回答的研究问题 |
|---|---|---|
| B0 | 无防御 RAG | 原始攻击能力和效用基准 |
| B1 | 旧 Rule-only，统一真实执行路径 | 已有模板规则能否处理自然改写/困难正常问题 |
| B2/B3 | 冻结 Judge + 拒答 / 无上下文 | 简单强干预能达到什么权衡 |
| B4 | 忠实 Mirabel + 目标隐藏 | 外部相似度方法的能力与局限 |
| B5 | 冻结 Judge + 隐藏并回填 | 检测证据与目标控制的基本组合是否有效 |
| B6 | 冻结 Judge + 降精度 | 中间粒度是否比整篇隐藏更保留效用 |
| Ours 候选 | 风险 + 目标定位 + 会话策略 | 动态动作是否在相同约束下改善最坏攻击表现 |

先用一个评分头做以上比较，减少组合爆炸。rubric/logprob、Top-k、模型变化放在稳健性实验。各方法可有自己的开发集校准参数，但必须使用同一效用约束、相同实验可观察信息、相同攻击预算与可比调参资源。可增加对所有请求常开改写的对照，以说明收益是否来自“仅干预部分请求”。

### 6.2 消融与失败归因

依次比较 Query-only / Query+Session；仅文本风险 / 加检索定位；隐藏无回填 / 隐藏并回填；统一动作 / 机制动作；无暴露记录 / 有暴露记录。一次只改一项，其余配置与样本保持一致。多轮策略应报告首次干预前已经泄露的信息，不能仅看最后一次拒答。

可以增加明确标注的 **oracle 诊断**：用真实攻击标签触发同一动作，或用真实目标 ID 定位，估计理想检测/定位下动作仍有多少不足。它只用于归因，不作为可部署方法，也不参与主要方法的公平排名。对 member 目标还可分别报定位召回、目标实际移除率；对正常问题报必要证据误删率。

### 6.3 固定回放与自适应攻击

固定查询回放用于配对比较。自适应阶段需要攻击者真正看到本防御的回答后再生成后续提问，并在 A-cal 上重选成员分数方向、阈值或分类器；所有方法使用相同总查询预算，失败/拒答仍计入预算。各策略分别维护独立会话，不能共享风险状态。

Query-only 评分可在输入/模型/Prompt 完全一致时按哈希复用；Session 评分只有完整输入和状态一致时才可复用。任何依赖历史回答或实际暴露的新策略均需重放。缓存实验与 live 延迟实验分开，不能拿缓存后的成本冒充线上成本。

## 7. 指标、阈值选择和统计口径

主表建议保留以下核心列，其余放附表，避免一个总分遮住权衡。

| 维度 | 主指标 | 方向与口径 |
|---|---|---|
| 成员泄露 | 自适应攻击 ROC-AUC；TPR@5% FPR，样本足够时加 1% | 攻击 AUC 越靠近 0.5 越好；先确定方向，补报 `max(AUC,1−AUC)` 作翻转诊断 |
| 正常任务 | 正确性、完整性/完成率、错误拒答率 | 所有正常查询都计入；拒答在可回答任务上记失败，不能剔除 |
| RAG 证据 | faithfulness、引用支持度、授权证据 Recall@k | 与正确性联合解释；空答案/无事实回答单列，不能靠空答刷高分 |
| 误伤 | 每查询、每会话至少一次误干预率 | 判定“动作影响正常用户”的操作定义预先冻结；不与 Judge FPR 混淆 |
| 成本 | live 端到端 p50/p95、额外调用/token、失败率 | 同硬件、并发、预热和生成长度设置；同时保留实际输出长度 |

攻击低 FPR 是“nonmember 被攻击者误认为 member”，与防御器把正常查询认成攻击的 FPR 不同。[Carlini 等](https://arxiv.org/abs/2112.03570)论证低 FPR 对成员推断评估的重要性，但其论文研究训练集成员推断；此处借用评测思想，需要在 RAG 目标级数据上重新定义。攻击阈值在 A-cal 冻结，测试报告实际 TPR/FPR；ROC 插值曲线作为描述性指标另报，不把测试曲线挑出的阈值声称为部署阈值。

正常质量可借鉴 [RAGAs](https://aclanthology.org/2024.eacl-demo.16/) 与 [ARES](https://aclanthology.org/2024.naacl-long.20/) 的分维度评估。建议抽取 200–300 个按问题类型和动作分层的样本作盲评，至少两名评审者，报告一致性；这是起始预算建议，按误差和成本调整。分层抽样的人评总体均值需按真实分层比例加权。评估模型与防御 Judge 分离，核查模型对拒答、短答、改写答案的偏好。

策略选择可以表述为：在正常质量损失、错误拒答和成本约束内，最小化各攻击中的最坏泄露。开发初期可预设示例约束：正常正确性绝对下降不超过 2 个百分点、错误拒答率不超过 1%，并单列困难正常组的下降；延迟上限根据 P0 的实测和使用场景确定。这些是待讨论的研究目标，非标准要求；若没有策略满足，报告不可行性，不能在看到 test 后放宽。对不同动作/阈值绘制完整 Pareto 曲线，避免只展示一个幸运工作点。

使用目标文档/近重复组做配对 bootstrap；同一文档所有攻击轮次、各方法输出一起抽取。正常会话按其来源文档/会话聚类，避免把关联查询当独立样本。报告 95% 区间、实际目标数、会话数与查询数；有生成随机性时对主要方法做至少 3 个种子，并分清目标抽样与生成随机性的变化。零错误不表示错误率为零；缺少独立样本时不能证明很低的 FPR。

## 8. 论文必须补的压力测试与呈现方式

侧信道实验让一个攻击器只看用户可观察的拒答样式、长度、引用和响应时延，再比较加入答案语义后的攻击能力。内部动作 ID 若部署不暴露，就不能交给攻击器；但它对应的外观变化需要计入。统一拒答措辞只能消除部分差异，并不保证成员/非成员输出分布相同。

另外检查新会话重置、攻击前插入正常问题、连续合法精读、早期 1–2 轮、相近目标文档和生成模型已有知识。可对一小组目标构造相同背景库的 `D` 与 `D\{target}` 配对索引诊断，量化变化是否由目标收录引起；这是辅助实验，需控制索引大小/背景差异并单独标注。

推荐论文材料为：一张主比较表（安全/质量/成本）、一张困难正常分组表、一张消融表；三张图（隐私—质量 Pareto、查询预算曲线、动作与错误类型分布）；若干失败案例。正文应展示至少一个“安全提升但质量下降”的案例和一个“被检测到但仍泄露”的案例，解释控制机制的实际边界。

运行清单至少包含数据/划分/索引哈希、Judge 及生成模型身份、Prompt/模式库、冻结模型、策略参数、攻击校准器、随机种子、软件/硬件与状态。结果保存逐轮记录、逐目标攻击分数、正常质量评估及失败清单；中断运行保留 completed/failed/skipped 数量，不删除失败后只报成功子集。

## 9. 最先值得完成的一组工作

第一批只推进 P0/P1 与小规模开发回放：把冻结 Judge 接入 observe；补上控制前/后证据审计；让拒答、无上下文、隐藏回填三个动作真正闭环；用同一批普通与困难正常问题及四类攻击比较。得到这些结果后，才能判断摘要是否值得其质量和调用成本，以及会话预算是否有实质增益。

本次只形成建议文档。实际完成组件或实验后，按项目规则更新状态与实验索引；新数据另建版本并登记数据目录。开发时继续引用原冻结产物，不覆盖历史模型、阈值和结果。
