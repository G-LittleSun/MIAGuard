# MIAGuard：面向 RAG 成员推断的访问控制防御文献综述与实验设计

更新日期：2026-10-22。本文是**文献解读与待验证的研究方案**，不是 MIAGuard 已完成的防御实验。论文中的数字只属于原作者的设置。项目状态与数据身份见[项目状态](PROJECT_STATUS_ZH.md)、[数据目录](DATA_CATALOG_ZH.md)、[实验索引](EXPERIMENT_INDEX_ZH.md)；出现冲突时以运行清单、冻结模型和结果 JSON 为准。

## 先用一个例子理解问题

假设私有检索库中可能有一篇公司收购新闻。攻击者看不到库，却可以向 RAG 系统提问。他不一定直接问“这篇文章在库里吗”，也可以给出开头让模型续写、遮住一个细节让模型填空，或连续问几个看似普通的事实问题。若“文章在库里”和“不在库里”时的回答有稳定差异，攻击者就能推断其**检索库成员身份**。这里的 member 指文档在 RAG 检索库中，**不是**文档是否进入基础大模型训练集。

我们的目标是：让可疑查询难以接触会暴露成员身份的证据，同时尽量保留正常问答的正确性、完整性与证据支持。所谓访问控制有两层：**静态授权**决定用户本来能读哪些文档；**动态风险控制**在已授权范围内根据查询和会话状态决定本轮给哪些证据、给多少细节。风险分数绝不能扩大静态权限。MIAGuard 当前重点是第二层；项目还不能声称已上线用户角色授权系统。

## 1. 最直接相关：Mirabel 的“发现异常相似，再只藏目标”

**来源：**Choi 等，[《Safeguarding Privacy of Retrieval Data against Membership Inference Attacks: Is This Query Too Close to Home?》](https://aclanthology.org/2025.findings-emnlp.438/)，Findings of EMNLP 2025。

**它要解决什么？** 普通 RAG 会把最相似的文档交给生成模型。很多成员推断查询恰好紧贴某一篇目标文档；若它进入 Top-k，模型可能复制原文或回答只有它才提供的细节。直接拒绝所有“太像文档”的问题则会误伤正常问答。

**具体怎样做？** 把检索相似度想成一张成绩单。正常问题可能有若干篇相近资料；攻击问题则可能有一篇得分“异常高”。Mirabel 计算查询与库中文档的相似度，暂时拿掉最高分，用其余分数估计背景均值和方差，再依据极值理论的 Gumbel 阈值判断最高分是否离群。若离群，它把最高分对应文档识别为可能目标，只在**本次请求**中将它从可用证据中隐藏，继续用其他文档生成。论文并非简单使用固定 Top-1/Top-2 差值；改用该差值属于新近似，必须另行验证。论文针对 S²、Masked 类攻击与 IA 等检查攻击和正常效用。

**直观例子。** 攻击者输入某报道的前半句，库中这篇报道比所有其他文章都相似。系统本轮不把它给模型，但可以使用同主题的其他报道回答宽泛问题。攻击者便较难利用准确续写推断收录状态。

**优点。** 只干预可疑证据，不必拒绝整个问题；不用改生成模型；“相似度异常 → 目标定位 → 证据过滤”的因果链清楚，适合做本项目的强外部基线。

**局限。** 方法依赖“攻击查询只与一篇目标特别相似”。语义改写、多个相近文档、多轮渐进探测或嵌入模型变化可能使离群点不明显。合法用户询问单篇独有的报告、日期或引文，也可能出现同样尖峰，被误藏后答案错误。统计假设和实际运行开销要在自己的语料上重测；论文附录也记录实际开销高于理论附加计算的情况。

**MIAGuard 可借鉴：** 将“是否干预”和“隐藏哪篇”拆成 Judge 风险判断与候选目标定位；实现本轮过滤后从剩余**允许文档**回填 Top-k。忠实复现 Mirabel 作基线；若改用简化的 Top-1/Top-2 信号，应称为本项目方法。专设“答案确实只在一篇文档里”的困难正常集。

## 2. 动态编排参考：ADO 的“先判风险，再开对应防线”

**来源：**Pallerla 等，[《Adaptive Defense Orchestration for RAG》](https://arxiv.org/abs/2604.20932)，2026 年 arXiv **未同行评审预印本**。

**它要解决什么？** 把所有防御常开看似安全，却会给正常 RAG 不断加噪、删除证据或额外审核。ADO 将系统分成“哨兵”和“策略师”：前者识别风险，后者选择对应防线和强度。

**具体怎样做？** Sentinel 综合当前查询、会话行为、用户信任和检索分布等信号判断威胁；Strategist 决定在检索、上下文、生成等哪个阶段施加哪种防御。成员推断、投毒与敏感内容泄露不必使用同一动作。其论文报告常开堆栈显著损伤 contextual recall，而按需编排回收部分检索效用。

**直观例子。** 用户问宽泛主题时保持完整检索；会话连续围绕同一篇私有文档探测细节时，才收紧这篇证据的访问。两类问题不承担同样的质量成本。

**优点。** 把风险判断与实际动作解耦，方便比较相同检测器下不同策略的价值；结构贴近 MIAGuard 已有的 Query/Session Judge 与动作骨架。

**局限。** 论文覆盖多种威胁，其策略与本项目四类 MIA 不一一对应。作者的可行性实验规模较小，每类攻击每数据集约 50 条良性与 50 条恶意查询，缺少系统化多轮时序评估。“消除 MBA 式泄露”指其特定片段重建口径，不能推广成所有成员推断攻击成功率为零。复杂编排可能增加尾延迟。

**MIAGuard 可借鉴：** 采用“风险/不确定性 → 动作选择 → 实际执行 → 审计”框架；先比较少量透明动作（不干预、目标隐藏、证据降精度、拒答），再考虑复杂策略师。不要迁移 ADO 的效果数字。

## 3. 权限底座：Chen 等的授权感知 RAG

**来源：**Chen 等，[《Integrating Access Control with Retrieval-Augmented Generation》](https://dbs-research.github.io/pdf/2025_sac.pdf)，ACM SAC 2025。

**它要解决什么？** 医疗机器人服务不同医生和护士。检索器找到“最相关病历”，不代表当前用户有权读它；生成模型不应先看到全部病历，再寄希望于提示词让它“不要说”。

**具体怎样做？** 将文档和权限关联，结合用户身份/角色，只用当前用户允许访问的病历来回答。论文以 40 份合成病人档案、两级访问权限做概念验证。关键是**先确定允许集合，再检索和生成**。

**优点。** 权限边界清楚、可审计，可在证据进入生成模型前阻断越权内容。日后若 MIAGuard 处理多用户、多密级语料，这一层是必要底座。

**局限。** 小规模合成医疗数据概念验证主要解决“谁能读”。已经有权查询某文档的用户仍可能用 IA 探测其收录状态；静态授权本身不解决这个问题。文档级许可也未必覆盖字段级许可。

**MIAGuard 可借鉴：** 将 `allowed_doc_ids` 视为动态动作的上界：先授权过滤，再计算风险与允许范围内的检索/回填。若增加角色实验，应将“越权访问”与“成员推断”作为不同评测维度。

## 4. 中间档：VAGUE-Gate 的证据降精度

**来源：**Hemmat 等，[《VAGUE-Gate》](https://aclanthology.org/2025.ijcnlp-long.194/)，IJCNLP-AACL 2025。

**它要解决什么？** RAG 有时需要敏感文档中的一般知识，却不需要把姓名、编号或原始措辞一并送给生成模型。全部遮盖使答案失去依据，原文全给又可能暴露细节。

**具体怎样做？** 在证据进入生成模型前，先删除低效用、可能泄露信息的 token，再做多轮高温改写，让剩余线索更难还原。作者在其定义的本地差分隐私机制与预算下，测词面/语义泄露、faithfulness 和时延。其 ε=0.3 设置下报告词面泄露降低 70%、保留 Plain-RAG faithfulness 的 91%、额外约 240 ms；这些数字仅适用于论文的数据与指标。

**直观例子。** 证据写“某公司在 2023 年 5 月 17 日完成 3.7 亿元收购”；改写后可能只留下“该公司在当年完成一笔大型收购”。回答“发生哪类交易”仍有帮助，回答准确日期与金额则不够。

**优点。** 提供“原文全给”和“整篇隐藏”之间的中间档，适合对可疑请求按粒度降级。

**局限。** 其主要目标是敏感内容泄露，并未直接证明成员身份不可推断。准确数字、实体、引文可能正是正常用户需要的；改写差异还可能形成新的成员信号。论文隐私保证绑定其具体机制与假设；普通摘要不能称为差分隐私。

**MIAGuard 可借鉴：** 设计可疑请求专用的证据降精度候选，分别测试语义问答与精确事实问答。必须真正生成并保存摘要，不能只返回 `summarize_context` 动作标识。

## 5. 输出侧补充：PAD 的敏感 token 解码控制

**来源：**Wang 等，[《Privacy-Aware Decoding》](https://arxiv.org/pdf/2508.03098)，**KDD 2026**，[DOI 10.1145/3770855.3817665](https://doi.org/10.1145/3770855.3817665)。

**它要解决什么？** 即使必须把检索片段给生成模型，也不希望模型逐字复述隐私信息。生成完成后删词可能太晚，其他词已经透露线索。

**具体怎样做？** PAD 在逐 token 解码时进行 logit 截断、筛选高风险输出位置，并向这些位置的 logits 注入校准的高斯噪声；用 Rényi DP 记账器跟踪其定义下的隐私成本。干预发生在“模型即将说什么”的时刻。

**优点。** 可作为检索侧控制后的第二道防线；比所有 token 一律加噪更可能保住一般流畅度。

**局限。** 需要控制生成 logits，闭源 API 可能无法实施；准确答案、数字、引文可能受损。论文的 γ-relaxed 保证只覆盖被保护的部分 token，记账依赖实际自适应噪声日程，不能简化成“整个回答对成员身份具有标准 DP 保证”。其主要研究内容抽取，不能直接等价于阻止本项目四类 MIA。

**MIAGuard 可借鉴：** 作为中长期输出侧对照。若实现，单列受保护 token 比例、攻击者重校准后的 MIA、答案质量和延迟，不能只报一个 ε。

## 6. 语料级替代：SAGE 与 DP-SynRAG

**SAGE：**Zeng 等，[《Mitigating the Privacy Issues in RAG via Pure Synthetic Data》](https://aclanthology.org/2025.emnlp-main.1247/)，EMNLP 2025。先从私有资料抽取有用属性并生成替代文本，再迭代改进。可理解为用“保留必要事实、弱化个体细节的合成档案”代替原始病历。优点是减少每次检索接触原文；局限是生成成本、事实保真、索引重建和合成文本仍可能记住个体细节。

**DP-SynRAG：**Mori 等，[《Differentially Private Synthetic Text Generation for RAG》](https://aclanthology.org/2026.findings-acl.62/)，Findings of ACL 2026。将差分隐私预算更多放在**一次性合成检索语料**上，生成后反复查询不再每次对原语料重新加噪。优点是大量重复查询时摊销成本；局限是预算、邻接定义、合成质量和正常问答变化都需逐项核对。

**MIAGuard 可借鉴：** 两者适合远期语料级强干预对照；它们并非“发现可疑查询后按需控制”的直接替代，早期不宜只用一个总分与动态策略比较。

## 7. 攻击文献为何提示需要多轮压力测试

以下是**攻击论文**，不是防御方案。[Naseh 等的 IA，CCS 2025](https://arxiv.org/abs/2502.00306)说明攻击者可连续提看似普通的事实问题；[Nguyen 等的 MEntA，USENIX Security 2026](https://www.usenix.org/conference/usenixsecurity26/presentation/nguyen-nguyen)提示少量自然提问也可能足够。因此不能只测试明显的“请续写原文”，也不能把“查询次数很多”当成攻击必要条件。MEntA 当前不在冻结 `ag_news_queries_v1` 中，未来加入应新建版本与冻结划分。

## 8. 适合 MIAGuard 的候选架构

下面是**拟研究流程**，不是现有系统已实现流程：

```text
用户身份/权限 → 限定允许检索集合 → Query 风险与会话状态
                                  ↓
                        检索及目标定位信号
                                  ↓
                 策略选择：完整 / 局部隐藏并回填 /
                         降精度 / 无上下文 / 拒答
                                  ↓
               实际交给生成模型的上下文 → 回答与引用
                                  ↓
             审计：分数、动作、证据、回答、延迟、失败
```

**候选动作。** 低风险请求保留授权后的完整 Top-k。对 Direct，避免显式确认索引收录；若还包含普通主题问题，可用其他允许证据回答。对 S²/Masked，比较目标文档隐藏并回填与证据降精度。对 IA，跟踪会话中的目标暴露与累积证据，而非只检查单轮关键词；持续升高的风险才考虑升级限制。高置信严重探测或没有足够替代证据时，拒答是兜底与强干预基线。此处是候选策略，阈值和动作映射尚未冻结。

| 攻击形式 | 攻击者想观察什么 | 首先比较的动作 | 最容易误伤的正常需求 |
|---|---|---|---|
| Direct：直接问收录状态 | 回答是否明确确认“库里有这篇” | 统一不确认索引状态；仍尝试回答可回答的主题部分 | 用户正当询问资料目录或出处 |
| S²：给出前缀求续写 | 是否能逐字接出目标原文 | 定位并隐藏目标片段/文档，回填替代证据 | 合法的引文核对、续写编辑 |
| Masked：遮住少量信息求恢复 | 是否能准确填回被遮事实 | 目标隐藏与降精度并列比较 | 合法的日期、金额、实体查询 |
| IA：多轮自然事实探测 | 多个回答合起来是否只有 member 时成立 | 会话级暴露记录，逐步降低目标证据可见度 | 合法的连续精读与研究问答 |

上表中的“攻击形式”是研究者离线分组使用的真值；部署时策略只能基于可观察信号推断可能的机制。对难以分类的查询，应评估统一的保守动作及其代价。

**关键警告。** 本项目旧 Rule-only IA 回放中，`restrict_context` 截成 Top-1 曾使 IA 攻击更强；“给更少文档”不等于“更隐私”，因为只剩目标时答案反而更依赖它。目标隐藏必须是本轮上下文过滤，不是永久删除共享索引；过滤后应在允许集合中回填，而非机械缩短上下文。动作本身也可能成为成员信号：若仅在 member 时出现明显拒答、引用减少或延迟增加，攻击者可以直接利用它。

**当前接入边界。** v3 Query/Session Judge 和两种冻结融合模型只完成离线识别，尚未接入在线网关。融合分数使用 `[x1, x2_observed]`，只覆盖 Session 分数可用的第 3 轮起；前两轮应单独设计 Query-only 策略，不能把缺失的 x2 当零。冻结阈值不能直接套入旧 `RiskAggregator.total_risk` 或旧 L0–L4 边界。`summarize_context` 在现有网关内未完成真正摘要，`ENABLE_RATE_LIMIT` 只是动作码。具体见[攻击识别阶段交接](ATTACK_DETECTION_STAGE_HANDOVER_ZH.md)与[阶段二 IA 评测](STAGE2_IA_POLICY_EVALUATION_ZH.md)。在线控制器不能读取真实 `membership_label`、`attack_type` 或目标文档真值；这些字段只可用于离线评估。Judge 超时、缺失或会话状态失败时，应显式记录并使用预定义的回退动作，不能静默当成零风险。

## 9. 论文写作中有说服力的防御实验：先分清三类指标

检测器的 AUROC/F1 只说明“能否识别可疑查询”，不能推出“防御后成员泄露下降”。真正的防御实验必须让攻击者看到**施加控制后的完整 RAG 回答**，再用这些回答判断 member/nonmember，同时测正常查询答案质量和系统成本。

### 9.1 安全性：攻击者最终还能猜多准？

| 指标 | 通俗解释与推荐口径 | 容易误读之处 |
|---|---|---|
| 攻击 ROC-AUC | 用攻击者从防御后回答得到的成员分数区分 member/nonmember；0.5 接近随机猜测。四类攻击分别报，再报宏平均。 | AUC 小于 0.5 时攻击者可能翻转方向。至少同时报 `max(AUC, 1−AUC)`，更重要的是让知晓防御的攻击者重新训练/校准。 |
| TPR@固定攻击 FPR | 例如攻击者只有 1% 或 5% 的非成员误判预算时，能找出多少成员；报告完整 ROC 与阈值选择集。 | 这是**攻击者**把 nonmember 错判为 member 的 FPR，不是防御 Judge 对正常用户的误报率。 |
| 攻击优势 | 固定阈值下 `TPR_attack − FPR_attack`；也可报告平衡准确率，但须写清定义。 | 不同论文的 “advantage” 定义可能不同，不宜只写名称。 |
| 查询预算曲线 | 横轴每目标允许 1、3、5、10、30 次等查询，纵轴攻击成功率/AUC；记录首次可靠推断轮次。 | 只看 30 轮终点会掩盖前两轮漏洞，也会漏掉少查询攻击。 |
| 输出与动作侧信道 | 比较 member/nonmember 的拒答、动作、引用数、长度、时延；训练只看这些信号的攻击器。 | 隐藏正文但暴露动作差异，仍算成员泄露。 |
| 精确恢复/内容泄露 | 对 S²/Masked 单列目标片段精确匹配、n-gram 重合和语义泄露。 | 它们衡量内容抽取，不等于成员推断 AUC；应分别报告。 |

最强的主结果应包含**知道防御存在的自适应攻击**：攻击者在独立开发集上观察防御输出，重选阈值/训练分类器，并在允许查询预算内改写提问。固定使用无防御攻击阈值只能作为补充。若原攻击没有连续成员分数，先定义可复现的攻击评分与决策规则；不能把防御 Judge 的风险分数充当攻击者成员分数。低 FPR 报告的动机可参照 [Carlini 等的成员推断评测论文](https://arxiv.org/abs/2112.03570)。

低 FPR 工作点需要足够多的**独立非成员目标**。例如只有 20 个非成员目标时，经验 FPR 的一个目标误判就对应 5%，无法可靠分辨 1% FPR；对同一目标重复生成更多相关查询不能解决独立样本不足。应在新保留集中增加目标数量、给置信区间，并在样本不足时明确标记该工作点不稳定。

### 9.2 正常效用：普通用户失去了什么？

| 指标 | 推荐做法 | 为什么同时要测 |
|---|---|---|
| 回答正确性 | 有标准答案时用 EM、F1 或任务特定准确率；开放问答用盲评人工判定和固定 rubric。 | 一个“有依据但没回答”的答复不能算成功。 |
| 完整性与可回答率 | 记录所需事实覆盖率、正常请求完成率、错误拒答率；区分“无证据而谨慎不答”和“有证据却被挡住”。 | 模糊回答可能高度 faithful，却失去用户所需事实。 |
| Faithfulness/证据支持 | 将回答中事实与**实际提供给模型的允许证据**逐条核对；测引用是否支持对应断言。 | 仅有正确措辞不足以证明其来自允许证据；只测 faithfulness 会奖励空泛回答。 |
| 检索证据覆盖 | 为合法问题标注必要证据，报告授权集合内 Recall@k、干预后证据保留率、替代证据有效率。 | 可定位质量下降来自检索、控制还是生成。 |
| 配对质量损失 | 同一正常问题比较无防御与各防御的质量差值和受损问题比例，按问题类型分层。 | 平均分可能掩盖少数单文档事实问题全部失败。 |

[RAGAs（EACL 2024）](https://aclanthology.org/2024.eacl-demo.16/)提供检索和生成质量的自动评估维度；[ARES（NAACL 2024）](https://aclanthology.org/2024.naacl-long.20/)强调 context relevance、answer faithfulness、answer relevance，并用少量人工标注校正自动评估。可引用它们作为指标依据，但论文主结论最好包含盲评人工子集、评审者一致性和典型错误案例。评估用 LLM 与防御 Judge 应分离，并在人工子集上检查评审偏差。

**必须扩充困难正常集：**合法的单篇精确事实、日期/金额/实体问答、短引文、同文档连续提问、与 IA 形式相似的研究型问答，以及可由多篇文档替代回答的问题。当前 `ag_news_queries_v1` 的正常问题类型有限，不能仅凭其平均质量估计上线误伤。

### 9.3 工程成本与策略行为

报告请求端到端 p50/p95 时延，并拆分 Judge、检索/过滤、摘要、生成；记录额外 LLM 调用和 token、吞吐、超时和失败回退。报告总体及各攻击类型的动作分布、目标定位准确率、实际过滤比例、回填后 Top-k 文档数。对正常请求同时给出**每查询误干预率**和**每会话/每文档至少一次误干预的比例**；后者更接近用户感受。若实现真实限流，还需报告额度触发率与合法用户被限流比例。

“Judge 良性 FPR”和“最终策略误干预率”应分开：Judge 报警后若只记录日志，用户未必受损；Judge 未报警却由其他规则触发过滤，也算实际干预。当前 v3 test 的观测良性 FPR 为 0，但良性样本仅约 60 条且记录相关，**不能**宣称线上误伤率为零或已满足 1% 上限。

## 10. 推荐实验协议、对照与论文图表

**固定比较条件。** 在同一批目标文档、成员/非成员配对、正常问题、检索器、生成模型、Prompt 和随机种子下回放完整 RAG；保存实际给生成模型的文档 ID/文本版本、回答、引用、动作与时延。成员/非成员目标按文档配平。攻击者只能看到部署时可观察的输出。用开发集选择策略与阈值，再在新保留集一次性评估。历史 test 已被查看，若复用须明示并将结论定为探索性。

**主对照表至少包括：**无防御；旧 Rule-only；Judge + 全拒答/无上下文；Judge + 目标隐藏并回填；Judge + 证据降精度；Judge + 按机制选动作。增加 Mirabel 忠实复现作外部基线；若资源有限，明确其尚未复现。可加“所有请求都隐藏或改写”的常开强保护对照。历史 `restrict_context` Top-1 可作诊断性反例，不能预设有效。

**消融实验。** 分别去掉 Session 分数、检索相似度、目标定位、回填和会话暴露记录；固定检测器只换动作，再固定动作只换检测器。前两轮单列 Query-only，不与第 3 轮后的双分数样本混报。按 Direct、S²、Masked、IA 和困难正常类型拆分，检查哪一步带来收益或误伤。

**统计与图表。** 主表同时列攻击 AUC/TPR@低 FPR、正常答案正确性/完成率/错误拒答率、p95 时延与样本数。画隐私风险—正常质量 Pareto 曲线、查询次数—攻击成功率曲线；给出动作与成员状态的混淆表以检查侧信道。置信区间用 `doc_id` 或完整会话为重采样单位做配对 bootstrap；生成有随机性时报告多个种子。不要把同文档几十条相关问题当独立样本。预先设正常质量下降、误干预与时延上限，再在约束内比较安全性，而非按 test 上最好看的点调阈值。

**可写入论文的结论须对应证据。** “检测 AUROC 上升”只说明检测性能；“成员推断 AUC 接近 0.5”需说明自适应攻击、反向 AUC 与预算；“正常效用保持”需正确性、完整性与困难正常集证据；“访问控制有效”需证明动作真实执行，且没有用拒答样式另造一个成员 oracle。

## 11. 下一阶段的实际顺序

1. 在开发数据上以 observe 模式接入冻结 Judge 分数，核对线上/离线特征、前两轮、超时与状态缺失；不改变回答。
2. 实现可审计的本轮目标隐藏、允许集合内回填、无上下文和拒答。若做降精度，保存真实摘要文本并检查它确实进入生成模型。
3. 冻结少量候选策略，建立困难正常集和自适应攻击评测；比较统一动作与按机制选动作，重点排查 IA 与单文档合法问答。
4. 固定策略后在新的保留集上做配对 RAG 回放，联合报告泄露、质量和成本。完成真实功能或实验后更新[项目状态](PROJECT_STATUS_ZH.md)与[实验索引](EXPERIMENT_INDEX_ZH.md)；产生新数据版本时更新[数据目录](DATA_CATALOG_ZH.md)。
