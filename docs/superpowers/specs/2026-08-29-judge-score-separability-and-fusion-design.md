# LLM-as-Judge 双风险分数可分性与融合实验设计

## 1. 目的与范围

本实验在冻结查询库 `ag_news_queries_v1` 与冻结文档级划分
`data/query_bank_splits/ag_news_threshold_v1.json` 上，检验当前
progressive LLM-as-Judge 的两个风险输出是否能将攻击流量与良性流量区分开，
以及二者是否具有可学习的互补信息。

本阶段的主任务是二元分类：

```text
benign = 0
direct_rag_mia / s2_mia / masked_mia / ia = 1
```

攻击类型不作为融合器输入，也不用于选择类型专属阈值。攻击类型仅用于诊断，
防止总体平均数掩盖对任意一种攻击（特别是 IA）的失效。

本设计不修改 Judge、攻击提示词、查询库、数据划分或测试集。它也不在验证集或
测试集上训练模型、调参数或选择阈值。

## 2. 当前可用的两个特征及时间语义

本实验并行评估两个既有评分头，不预先指定 `logprob` 为主评分头：

```text
head = logprob: x1 = query_trace.logprob.score; x2 = session_trace.logprob.score
head = rubric:  x1 = query_trace.rubric.score;  x2 = session_trace.rubric.score
```

两种评分头分别走完全相同的数据审计、可分性图、分组 OOF、融合和阈值选择协议，
不得将四个分数在未经预先定义的消融设计下直接混合。这样比较回答的是“哪种 Judge
评分头更适合作为风险信号”，而不是让一个融合器通过额外特征数获得不公平优势。

风险记录显示当前会话检测器在前两轮产生
`statuses.overall = insufficient_history`、`routing_decision =
DEFER_INSUFFICIENT_HISTORY`；示例中 logprob 的 x2 为默认锚点 `0.1`，rubric 的 x2
为默认低档值。从第 3 轮开始才产生正常的会话评分。因此默认值不是“低会话风险”的
观测值，分析中不能把它与有效 x2 混为一谈。

派生字段定义如下：

```text
session_score_available = 1  if session_trace.statuses.overall == "ok"
                          0  otherwise
x2_observed = x2 when session_score_available = 1; missing otherwise
```

所有分析遵守前缀语义：第 t 轮只可使用第 1 至 t 轮的 Judge 输出。若当前记录的
session trace 来自完整会话回填，则该记录只能用于事后审计诊断，不能用于在线防御
主结论；本次数据审计必须在分析前验证这一点。

## 3. 数据审计与分析单位

1. 只读取 train 分区的 `judge_records.jsonl`；每个记录必须匹配同一
   `scoring_identity_sha256`、query bank 和 split ID。
2. 检查每个 `session_key` 只对应一个 doc、traffic type、attack type，并检查
   turn index 连续、无重复、无跨分区记录。
3. 主部署评价单位为“逐查询决策”，因为访问控制在每轮请求时发生；模型验证和
   bootstrap 的重采样单位为 `doc_id`，以避免同一文档内查询与会话的相关性造成
   伪重复。
4. 同时输出会话级补充指标：攻击会话是否至少一次触发，以及良性会话是否至少一次
   误报。会话级指标不替代逐查询的主阈值约束。
5. 对第 1–2 轮和第 3–5 轮分别统计；第 1–2 轮不把 `x2=0.1` 作为真实分数。

## 4. 阶段 A：不训练分类器的可分性诊断

本阶段只描述数据，不拟合高斯分布，不选择阈值，也不产生部署结论。

### 4.1 核心图表

全部图形采用可复现的顶级会议/期刊风格：Okabe–Ito 色盲友好配色、统一单栏/双栏尺寸、
固定字号与 `[0,1]` 坐标、弱网格和最少边框；同时输出 300 DPI PNG 与嵌入字体的矢量
PDF。禁止 3D、装饰性渐变和依赖颜色单独传达标签；稀疏分箱必须标注样本量并加纹理，
所有标题、图例和轴标签在论文缩放尺寸下仍须清晰可读。

1. 联合条件密度三联图：仅限 `session_score_available=1` 的第 3–5 轮，依次画
   `P(x1,x2|benign)`、攻击类型宏平衡的 `P(x1,x2|attack)` 和两者的截断
   `log2` 密度比。三图使用同一 bin、坐标与密度尺度；密度比是主可分性证据，而非
   被类别数量影响的原始攻击比例。
2. 攻击类型富集小倍图：四面分别为 Direct、S²、Masked、IA 相对 benign 的 `log2`
   密度比，使用相同的发散色标和稀疏格纹理。它们是误差分析，不是多类训练或类型
   专属阈值。
3. 边缘频率图：以 benign、四攻击类型为行，分别显示 x1 与有效 x2 的组内、文档
   平衡概率质量。Rubric 保留离散档位，logprob 使用固定 bin；不用 KDE 或高斯拟合。
4. 会话时间语义图：展示第 1–5 轮的 x1/x2 分布摘要和 x2 可用率，明确第 1–2 轮
   只有 x1，不能把默认 x2 分数画在低风险区域。

攻击密度必须先让每种攻击类型总权重相等，再在每种类型内让 doc_id 权重相等；良性
密度同样按 doc_id 平衡。另可报告未加权原始样本量，但不得让 IA 的更多查询支配主图。
对于 logprob 使用固定二维 bin；对于 Rubric 的离散档位，图中保留评分格点的占用结构，
不得用平滑核密度暗示连续正态分布。

### 4.2 描述性统计

按评分头、benign、all-attack 和四个攻击类型报告 x1/x2 的样本数、缺失率、均值、标准差、
中位数、IQR、5/25/75/95 分位数。报告 x1 与 x2 的 Spearman 相关（总体及分标签），
并报告其 bootstrap 区间。相关不等同于互补性：最终仍须用交叉验证性能验证。

不以正态性检验、单一 p 值或目测散点图来宣称“可分”。评分具有离散锚点、截断和
非高斯形状的可能，使用经验分布更合适。

## 5. 阶段 B：受限模型比较，验证是否存在互补增益

使用只在 train 分区内部进行的、按 doc_id 分组的 5 折交叉验证。每折的所有预处理
（缺失填补、标准化、正则强度选择）只在该折训练文档上拟合。产生所有训练记录的
out-of-fold（OOF）攻击概率。

为避免 IA 的查询数量远多于其他类型而主导训练，每个训练折内部使用固定的分层样本
权重：benign 总权重占 1/2，四种攻击各占 1/8；每种流量内部先让各 doc_id 权重相等，
再让同一文档内查询平分该文档权重。权重只由训练折标签和分组计算，不传入验证折；
评价仍按原始样本及文档平衡指标进行，不复制或删除查询。

比较下列预先指定的模型：

| ID | 模型 | 用途 |
| --- | --- | --- |
| B1(h) | 评分头 h 的仅 x1 的 L2 正则逻辑回归 | 查询级基线 |
| B2(h) | 评分头 h 的仅 x2_observed 的 L2 正则逻辑回归，仅评估 x2 可用轮次 | 会话级信号能力 |
| B3(h) | 评分头 h 的现有人工加权规则 | 旧方案基线；权重保持原值且不重调 |
| M1(h) | 评分头 h 的 x1、x2 的 L2 正则逻辑回归，加 `session_score_available` 缺失指示 | 主学习融合器 |
| M2(h) | 深度不超过 2 的决策树或同等受限非线性模型 | 仅检验明显非线性，不作为默认主模型 |
| M3(h) | 固定的浅层 MLP：3 → 4 (ReLU) → 1 (sigmoid)，输入为 x1、填补后的 x2 和可用性指示，使用 L2/weight decay | 预注册的敏感性实验，不作为默认主模型 |

在 M1 中，x2 缺失以固定值 0 填补并加入可用性指示；x2 在定义域 [0,1] 内，指示能
使模型区分“真实低分”和“无会话证据”。如审计发现 0 有语义冲突，可改为折内中位数
填补，但必须保持缺失指示，且在预先记录的规则下固定。

多层**线性**层没有非线性激活时可合并为一层线性变换，数学上等价于逻辑回归，不能
表达更复杂的分类边界。M3 使用 ReLU 才是真正的非线性模型；但输入仍只有二维，它不
会创造新的信息，且有效独立文档量约为 60，因此只能作为严格固定结构的敏感性实验。
只有当 M2 或 M3 在 OOF 的低 FPR 区域稳定优于 M1，且不会降低最弱攻击召回时，才可
在冻结前作为候选；validation 中的预先指定对照只用于报告，不能据此改选模型。否则
采用 M1，优先可解释性。

## 6. 评价、模型选择与阈值选择

### 6.1 可分性和互补性的判据

对每个评分头和模型，在 OOF 预测上报告 AUROC、PR-AUC、benign FPR、四攻击类型召回、
攻击宏平均召回、最弱攻击召回，以及 x1-only 与 M1 的差值。用 doc_id 分组的 1000 次
bootstrap 计算区间。

将“x2 有可用增益”定义为：在预注册的 FPR 约束点，M1 相较 B1 的攻击宏平均召回
改进的 bootstrap 区间不跨 0，同时良性 FPR 没有超过该约束。若不满足，主方案保留
x1-only，结果应如实表述为当前 x2 没有证明增益。

M2/M3 只有在其相对同一评分头 M1 的低 FPR 宏平均召回改进也稳定、且不会降低最弱
攻击召回时，才作为备选模型；否则采用 M1，优先可解释性。

部署候选评分头也只能在 train OOF 上选择：先比较其最终入选模型在主 FPR 约束下的
攻击宏平均召回，再比较最弱攻击召回和良性 FPR。两种评分头在 validation/test 的
预先指定对照结果可以完整报告，但不得根据这些结果更换部署候选或阈值。

### 6.2 阈值

ROC 曲线用于展示所有阈值下的 TPR/FPR 取舍，不用 accuracy 选点。主阈值在 train
OOF 概率上、而非 in-sample 概率上选择：

```text
在 benign query FPR <= alpha 的候选阈值中，
1. 最大化四攻击类型宏平均召回；
2. 再最大化最弱攻击类型召回；
3. 再最小化 benign FPR；
4. 其余完全相同时采用预先定义的确定性阈值规则。
```

alpha 的主值应在训练前固定（若没有明确业务安全要求，主文不声称唯一“正确”的值），
并同时完整报告 1%、2%、5%、10% 四个约束点的曲线/表格。准确率、F1 和 Youden J
可作为补充，不用作安全阈值的主选择准则。

## 7. 阶段 C：冻结、独立验证和测试

仅当阶段 B 结束后，冻结以下内容：特征定义、可用性规则、模型类、正则参数、模型
权重、阈值选择规则、alpha、Judge 配置和数据版本。

1. 在所有 train 文档上按冻结配置重新拟合模型。
2. 将冻结模型和阈值原样应用于 validation；只报告指标和区间，不再选择模型或阈值。
3. validation 不用于改提示词、会话规则、特征或阈值。若结果不达标，记录失败并回到
   新版本实验，而不是对同一 validation 集反复调参。
4. 只有方案完全锁定后，才对 test 做一次最终评估。

完整会话结束后的回填分数如被研究，必须单列为 post-hoc audit 上界；不得与前缀在线
评分的主访问控制曲线或结果混合。

验证和测试从锁定产物运行，未重新拟合或重选阈值。
