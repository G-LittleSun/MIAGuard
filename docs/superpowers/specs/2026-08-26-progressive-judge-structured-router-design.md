# Progressive Judge 结构化 Router 修复设计

## 背景

开发集中的普通良性会话曾被模型输出为 `REVIEW`，但候选攻击类型为空。
这不是单纯的 JSON 截断：输出在语法上是有效 JSON，却违反了 Router 协议中
“`REVIEW` 必须至少有一个候选攻击类型”的语义约束。对该输出追加修复提示后，
本地模型仍会重复同一矛盾，说明需要同时改进语义流程和输出约束。

## 目标

1. 让模型先判断可观察到的攻击机制是否存在，再在需要时判断攻击类型。
2. 将四类攻击的必要机制、反例和边界写清楚，避免把普通阅读、创作或练习误认为攻击。
3. 在 Transformers 本地推理中限制 Router 的 JSON 输出结构，禁止产生空候选的 `REVIEW`。
4. 不读取 membership、attack_type、target_doc_id 等离线真值字段；Judge 仍只根据查询、会话和可见检索行为判断。

## 新数据流

```
冻结查询 / 会话
        |
        v
Router Gate：是否存在可观察攻击机制？
  | 无攻击线索 / 明确良性 / 需要复核
  |                         |
  |                         v
  |                 Router Candidate：选择 1--2 个攻击类型和观察证据
  v                         |
SKIP_* <--------------------+
        |
        v
Verifier（读取所选攻击卡） -> Rubric / Logprob -> 后续阈值学习
```

Gate 只做机制存在性判断，不能猜测攻击类型；只有 Gate 返回 `REVIEW_REQUIRED`
才调用 Candidate。Candidate 的输出模式在 JSON Schema 中强制至少一个、至多两个且
不重复的候选类型。程序只将模型明确选择的 Gate 标签映射为路由决定，不替模型作
攻击语义判断。

## 攻击语义边界

- Direct RAG-MIA：必须同时有特定文本、针对私有 Context/检索证据的存在性或支持性检查、以及会泄露该存在性的回答请求。仅问文章内容、只出现 `context` 字样或检查公开文章都不构成该机制。
- S2-MIA：必须有源文本式前缀，并要求根据 Context/证据恢复已有文本的后续内容。创作续写、改写、摘要和明确要求原创结尾不是该机制。
- Masked MIA：必须同时有掩码/缺失片段、源文本式上下文，并要求从 Context/证据精确还原原文。普通填空、语法练习或任意合理补全不是该机制。
- IA：必须是同一目标的连续、受约束的事实探测；冻结查询库中默认要求至少三轮 Yes/No/Unknown、重复 Top-1 和多个事实维度。普通多轮阅读问答、同一事实的改写、或仅重复检索都不构成该机制。

## 结构化约束

使用 `lm-format-enforcer` 的 Transformers 集成，把每次 Router JSON 的合法前缀传给生成过程。
它保证 JSON 字段名、枚举值、数组长度和候选数组非空等结构条件；`parse_*` 函数仍保留
运行时校验，作为版本兼容和逻辑防线。语义判断错误（例如把普通阅读误判为存在攻击机制）
仍需通过上述攻击边界、开发集对照和后续指标来评估，不能把结构约束误当成语义正确性保证。

## 验收

- Gate 和 Candidate 的 schema 能拒绝 `REVIEW` 加空候选这一类状态。
- Query/Session Router 提示包含四类攻击的必要条件与良性边界。
- 现有 Judge 单元测试与新增 Router 测试通过。
- 对此前失败的 Windows 良性会话运行 smoke，Router 不再因空候选的 `REVIEW` 中断。
