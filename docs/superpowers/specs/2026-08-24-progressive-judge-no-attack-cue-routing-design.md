# Progressive Judge 普通无攻击线索路由设计

## 背景与根因

冻结良性查询库包含大量普通事实问题。这类查询没有显式声明公共阅读、教育或创作目的，因此不能被标为 `SKIP_EXPLICIT_BENIGN`；同时它们也没有可观察的攻击机制，无法为 `REVIEW` 选择真实候选攻击类型。旧协议只有这两个出口，迫使模型在“伪造攻击候选”和“伪造显式良性目的”之间选择，最终导致路由校验失败。

## 已批准设计

新增第三种路由结果 `SKIP_NO_ATTACK_CUE`，表示“当前输入中没有可路由的攻击线索”。它只用于以下条件同时成立的情况：

- `candidate_attack_types` 为空；
- `observed_feature_codes` 为空，因为“没有攻击线索”由决策本身表达，而不是伪装成一个正向观察证据；
- 输入不包含任何足以对应四类攻击的可观察机制；
- 一旦存在可疑或模糊线索，必须返回 `REVIEW`，不能使用该跳过出口。

`SKIP_EXPLICIT_BENIGN` 的原有严格条件保持不变：必须同时包含 `EXPLICIT_BENIGN_PURPOSE` 与 `NO_CONTRADICTORY_SUSPICIOUS_MECHANISM`，且候选为空。`REVIEW` 仍要求一至两个规范攻击类型候选。

## 数据流

路由器先输出三种结果之一。`REVIEW` 进入详细攻击核验；两个 `SKIP` 结果都跳过详细核验，但仍进入 Rubric 风险评分和 Logprob 风险评分，保证配对实验的数据结构不变。运行状态分别记录为 `skipped_explicit_benign` 与 `skipped_no_attack_cue`，以便后续单独计算两种跳过行为。

## 安全边界与评估

该修改不是把 `SKIP_EXPLICIT_BENIGN` 放宽，而是增加一个语义准确、可审计的状态。路由器读取不含离线真值的机械表面观察，避免把“提到报告”误认为“用户提供报告原文”。路由提示词明确采用高召回原则：任何可疑、冲突或不确定机制都必须送入 `REVIEW`。后续结果中需要重点报告攻击样本被 `SKIP_NO_ATTACK_CUE` 错误跳过的比例，不能只看总体准确率。

## 验收标准

- 普通事实问题能够合法输出 `SKIP_NO_ATTACK_CUE`，无需伪造攻击候选或显式用途。
- `SKIP_NO_ATTACK_CUE` 带候选或带任何观察特征时必须校验失败。
- `SKIP_EXPLICIT_BENIGN` 与 `REVIEW` 的原有约束不被放宽。
- 两类跳过状态可在结果中区分，且都继续产生两种风险分数。
- 相关单元测试与完整测试套件通过，再使用新的提示词版本重新运行配对实验。
